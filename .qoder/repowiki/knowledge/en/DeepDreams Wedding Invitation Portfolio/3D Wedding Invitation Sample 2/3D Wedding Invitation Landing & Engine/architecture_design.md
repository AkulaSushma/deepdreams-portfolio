Three-file single-page application loaded by `index.html`, which also contains an inline `file://`-protocol shim that strips `?v=…` cache-busting query strings from linked assets so the page works when opened directly from disk. `config.js` exposes a single `window.WEDDING_CONFIG` object (couple, events, venue, theme, frame paths, films, scratch message) and merges it at runtime with an override from `?c=` base64-encoded data, a `?draft=1` localStorage entry, or a server-published `window.DD_HYDRATE` content — deriving hashtag, city and short date from the couple's fields. `app.js` is the self-contained engine: it reads `CFG` to hydrate DOM text and meta tags, sets CSS custom properties from the theme, then initializes independent subsystems encapsulated as IIFEs returning small public APIs — audio (Web Audio API synthesized temple bells, whoosh, scratch noise, background music with fade/pause/restore around the 3D world), a bitmap ring buffer (`createBitmapRing`) that pre-decodes frame images into ImageBitmaps with eviction and full prebuffer modes, a scrub renderer that maps scroll position to frame indices with interpolation and hi-res fallback, a measured auto-fit name board that publishes a reserved height band so artwork never overlaps names, a petal particle system, and a scratch-card module. The 3D world is not embedded here; the app links out to `invitation.html#finale` and coordinates audio pause/restore across the transition.
