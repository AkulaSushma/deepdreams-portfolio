Three cooperating sub-applications live side-by-side in the same root directory but are otherwise independent: `index.html` serves the studio landing, `invitation.html` hosts the guest-facing engine (`app.js`, `studio.js`) that renders frame cinema, petals, scratch card, countdown and RSVP, and `create.html` hosts the no-code editor (`editor.js`). All three pages consume the same `assets/` tree (frames, films, audio, stills) and resolve couple data through a single source of truth — `config.js`, which merges sample defaults with a published payload, a `?c=<base64url>` shared link, or a `?draft=1` localStorage draft and exposes the result as `window.WEDDING_CONFIG`. The 3D baraat lives under `world/` (built from `3d-world-source/` via Vite + Three.js) and is not bundled into the invitation; navigation to it is a normal same-origin link enhanced by a CSS-only Rajputana torana transition so heavy WebGL assets load only on entry. The invitation passes only play/mute intent across the portal boundary, and the world starts its own soundscape on first gesture. The editor persists drafts to `localStorage` under `wedding-studio-draft` and can export a config download or shareable link that the invitation later consumes.
