Three files form a single-page editor: `create.html` is the shell that loads shared publishing primitives (`/shared/limits.js`, `/shared/publish-client.js`), a generated `config.js` (which defines `window.WEDDING_CONFIG` / `WEDDING_DEFAULTS`), and the two scripts. `editor.js` owns all editor state in a plain object `S` (couple, wedding, venue, rsvp, scratch, sanctum, films, theme, events) loaded from URL `?c=` base64 payload or `localStorage` draft key `wedding-studio-draft`, then binds every input through a small `bind(id, get, set)` helper so changes flow into `S` and trigger `sync()` + debounced `save()`. A contextual live-preview panel mirrors only the currently open step (couple → functions → venue → videos → blessing → palette → launch) via scene toggling on `#pv-card`. Publishing is delegated entirely to `window.DD_PUBLISH.publish` / `.recover` — this file never stores or validates activation codes; it strips local-only `blob:`/`data:`/`file:` video sources before sending the payload. `studio.js` is a separate landing page script for the studio site itself (brand hydration, scroll-driven phone mockup using pre-rendered frame images). Dependency direction is one-way: HTML → config → editor/studio scripts; no cross-import between them.
