The `api/` tree contains all business logic (admin, publish, invite, cron) written against a plain `(req, res)` interface plus shared utilities in `api/_lib/`. Each file under `netlify/functions/` is a one-line wrapper that imports the corresponding handler from `api/` and runs it through `netlify/lib/bridge.js`, which converts Netlify's `event` object into the Node-style request/response objects the handlers expect. This makes the hosting layer swappable: moving to another provider only requires rewriting the bridge, not touching any handler code. A separate `netlify/build.js` script assembles the static site into `dist/`, explicitly excluding `api/`, `netlify/`, and other non-public assets so only the rendered website is deployed alongside the functions.
