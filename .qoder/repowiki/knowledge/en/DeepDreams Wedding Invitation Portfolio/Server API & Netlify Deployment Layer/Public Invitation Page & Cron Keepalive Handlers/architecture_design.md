Two parallel deployment targets share the same runtime logic via a thin bridge pattern. `netlify/functions/invite.js` is a Netlify Function that parses `/invite/{slug}` from the path, decodes it, and forwards it as a `slug` query parameter to the shared handler in `api/invite.js`. The Vercel counterpart at `api/invite.js` is the actual business logic: it validates the slug against token rules, reads the site row via PostgREST (`db.getSiteBySlug`), builds a public view with `publicView.toPublic`, fetches the per-deployment HTML template into an in-process `Map` cache (with a 5s abort timeout), and renders the page with CDN-friendly `Cache-Control` headers (`s-maxage=60, stale-while-revalidate=86400`). `netlify/functions/cron-keepalive.js` is a separate Netlify Function that delegates to `api/cron/keepalive.js` through the same `bridge`, gated by a `CRON_SECRET` check so only the scheduled runner or authenticated callers can execute it; it exists as a debuggable mirror of the unwatchable scheduled job.
