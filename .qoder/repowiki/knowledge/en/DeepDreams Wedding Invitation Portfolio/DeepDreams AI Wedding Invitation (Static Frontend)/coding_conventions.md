- Runtime state is held in a single `DATA` object populated from defaults, localStorage drafts, or a decoded URL hash, and re-rendered via `data-bind` attribute matching against field keys.
- Each interactive ceremony is modeled as a mode string (`rub|trace|tap|light`) with a corresponding entry in the `MODES` map (label, hint, color, inline SVG art) and a `mountXxx` function registered in the `MOUNT` registry.
- User-facing strings derived from `DATA` are passed through a local `esc()` helper that escapes `&`, `<`, and `"` before insertion into innerHTML.
- Guest links carry all invitation data compressed with LZ-String in the URL hash (`#d=...`), while editors persist drafts to `localStorage` under the `dd_wedding_draft` key.
- Ceremony poster images whose paths start with `posters/` are treated as defaults and receive CSS-only text overlays generated by `buildPosterOverlay` rather than being edited in place.
- Audio feedback is produced on-demand via the Web Audio API (`ac()` lazy-initializes `AudioContext`) rather than loading external audio files.
